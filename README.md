# 飞花斯普拉遁 · 在线对战

两人开房、轮流落墨的飞花令涂色对战。**没有主持人**：句子是否成立由服务端语料判定，
判完给出处，双方都能当场核对。与单机版《飞花斯普拉遁-主持台》完全独立，互不影响。

```bash
node server.js          # 默认 8787 端口，浏览器打开 http://localhost:8787
PORT=9000 node server.js
```

零依赖，只需要 Node ≥ 18（用到内置 fetch / zlib / crypto）。不需要 npm install。

## 怎么玩

1. 一方填名字 → 「创建房间」，拿到 3 位数字房号 / 分享链接（房号从 `000` 起按顺序发，取第一个空号；最多 1000 间）；
2. 对手在同一页面输入房号加入，或者在大厅的「当前房间」列表里直接点「加入」；
3. **两人到齐还不算开局**：各自点一次「我准备好了」（可取消），两边都准备好才真正开始；
4. 轮流提交一句诗（每手限时，默认 120 秒、建局时可改，超时自动放弃）：句中出现的字会给棋盘上对应的格子上色，
   抢到对手的格子记「抢夺」，每手至少要占用一个未涂色格；
5. 对局中任意一方都能点「暂停」冻结倒计时（两边都能点「继续」）；
6. 棋盘填满、或轮数用尽即结算，比谁涂的格多。可「再来一局」（再来一局同样要双方准备）。
   中途想回退或提前结束，用「撤销一步」「提前结算」——两者都需要<b>对方点同意</b>才生效。
7. **观众**：房间坐满后仍可进来看（大厅按钮会变成「观战」）。选手随时可以「下场观战」，
   位子一空计时就冻结；任何观众都能点「坐到赤/青营」补上，两人坐齐自动继续。
   观众只能看，**不能裁决**，也看不到对方的输入。
8. **未收录的一手**：提交的句子语料里查不到时不直接判负，而是**暂停计时**，由对方**或裁判**裁决——
   判「有效」就按字面正常涂色入账（记录标「对方裁定有效」，裁判裁的则标「裁判 XX 裁定有效」），
   判「重填」则计时续走、换一句再来。
   提交方只能「撤回提交」。
9. **开局设置**：正式开局前，选手与裁判都能改**棋盘路数（5–17）/ 额外字 / 轮数 / 每手秒数 / 语料文体**，
   也能**重抽棋盘**（只换一套字，尺寸不变）。改完双方要重新点「准备好了」——规则变了，旧的准备不算数；
   开局后这整块面板收起，规则锁死。
10. **出手预览**：轮到你时，输入框里打出的字立刻在棋盘上刷成**你方墨色的半透明版**：
    实线内框＝新占、虚线框＝抢夺、白内框＝续色，输入框下方同时给出「将命中 N 格 · 新占 / 抢夺 / 续色」，
    没有未涂色格时会直接提示「落不下去」。落子后本手变化的格子会**闪一圈白描边**（1.05 秒褪去）。
11. **裁判**：选手可以在成员面板把任意观众「设为裁判」（可设多位，可随时取消）。
    裁判不能出手、不能点准备，但能**暂停 / 继续、撤销一步、提前结算、改开局设置与重抽棋盘**，
    也能裁决未收录句、代批选手的「撤销 / 结算」请求。裁判自己点撤销与结算是**直接生效**的，不用等谁同意。
    裁判身份跟着 `mid` 走——下场、补位、改昵称都不丢。
12. **房间成员**：右栏「房间」面板列出所有人——赤营、青营、观众（带「裁判」徽标），带在线状态与「你」标记。
    任何人可以随时**改自己的昵称**（点自己那行的「改昵称」，回车保存、Esc 取消），
    席位和身份都不会因此变化。
13. **离开与掉线**：点「离开房间」会先把身份从服务端摘掉（席位当场空出），再回大厅。
    直接关网页的人会被标成「离线」：观众离线 1 分钟后移出名单，选手离线 3 分钟后自动下场
    （席位让出来，计时冻结等补位）。在场的选手也可以手动**移出已经掉线的成员**——
    在线的人踢不掉，避免拿它赶走对手。
14. **重新进来**：用同一个昵称再次加入，会直接接回原来的席位（席位还占着、人已离线时换发新 token 接管）；
    如果原来是自己点「离开房间」走的，席位已经空出，同名加入也会坐回同一个位置。
    同名的另一个人不会顶替在线的玩家。
15. **房间事件**：右栏「房间」面板的第二个页签，记的是**飞花记录看不到的事**——
    谁进谁出、谁坐下谁下场、谁准备好了、谁暂停、谁发起撤销、谁同意、裁决结果、改名、调整设置、重抽棋盘、设/撤裁判、结算。
    每一手飞了什么是「飞花记录」的活，这里不重复。
16. **默认昵称**：名字留空时，从语料作者里随机取一位（14,769 位可用，都是 2–6 个纯汉字），
    进来就预填在输入框里，不合适可以改，改完浏览器会记住。取名在服务端做，前端拿不到作者表。
    输入框右边的**骰子**可以随时再换一位（图标是内联 SVG，不依赖 emoji 字体）。
17. **在房间里改的名字同样会被记住**：改名成功后写回浏览器，下次重进拿的就是新名字 ——
    只记大厅那个输入框的话，重进会拿着旧名（认不回席位，还会在成员列表里冒出「旧的你」）。
18. **记录的排版**：飞花记录与事件里的诗句一律用**空格分句**，不带标点 ——
    命中语料的句子底本带「，」、未收录的是归一化后的连续汉字，两种排版混在一起没法读。
    判定与落子只看归一化后的汉字，空格纯粹是给人看的。
19. **大厅**：左栏「开一局」、右栏「当前房间」。房间列表不自己滚动，房间多了就把整页撑长；
    排序是**进行中（房里还有人）→ 能坐进去的 → 满员观战**，确保真正在进行的对局始终排在前列。
    人去楼空的房间（没有席位也没有观众）10 秒内被清扫掉，不再占着房号。
    每条房间写明「规格 · 文体 · 额外字」；一方离开或还没坐下时，那一侧统一显示灰字**空位**（不再出现「—」）。
    局内顶部的「第 xx 轮」行同样带上文体与额外字，开局后不用回头翻设置。
20. **同一昵称反复进出**：会和「同名、且已经没有活连接」的旧记录合并成一条（mid 不变，
    裁判身份因此保住），不会在成员列表里堆出好几个「你」。
21. **说词儿**：「等 xx 说词儿」＝轮到对方；自己这一手输入框是可写的，提示为「轮到你了：输入一句诗词，回车提交」。
22. **导出**：结算弹窗与操作台上都有「导出截图 / 导出 GIF」，GIF 是逐手回放（至少飞过一手才有）。

房主只是建房的人，**没有额外裁决权**——判罚完全由服务端完成，裁判只是「人肉流程管理器」。

## 判定是怎么做的（核心）

**用权威语料做等值检索，不把大模型当裁判。** 理由很实在：判定必须可复现、可举证。
同一句永远同一结果，判错了能拿出「见《静夜思》李白」——这两条只有检索能同时满足；
大模型同一句两次可能给出不同答案，还会编出处。

```
提交 → 归一化 → 篇内连续检索（整句 / 跨小句连写 / 名句片段） → 异文对重查 → 通过 / 未收录
```

| 环节 | 做什么 |
|---|---|
| 归一化 | NFKC、去标点空白、繁体转简体（单字表 `data/t2s.json`） |
| 篇内检索 | 语料按标点切成小句存，另外拼一份「整首诗连写」的副本 `pb`；判定 = `pb.indexOf(q)`。篇与篇之间留着 `\n`，所以不会跨篇拼出假句 |
| 跨小句连写 | 玩家照通行本断句提交「故国神游，多情应笑我，早生华发」时，语料里是「故国神游 / 多情应笑 / 我早生华发」三个小句 —— 逐小句查永远对不上，必须在整首诗的连写文本上查。命中跨 2 个小句记「联句」，3 个以上记「跨句连写」 |
| 名句片段 | 不是整句、但 ≥5 字且在语料中出现的，也算引用（`半句` 也能落地） |
| 异文对 | 干/乾、着/著、征/徵、唯/惟、沈/沉、傍/旁、全/浑（版本异文，如《石灰吟》语料作「全不怕」、教材作「浑不怕」）互换后重查，**不做通用编辑距离**（5 字句距离 1 的邻域是十几万量级，等于放开伪造） |
| 出处 | 命中位置 → 诗篇（二分）→ 覆盖的小句区间，给出 标题 / 作者 / 朝代 / 文体 |

实测（本机，3,288,184 句语料）：**热判定中位 6.5 ms，p95 21 ms**；最坏路径（真句尾巴接垃圾，
需要把整篇语料扫完并试遍异文）约 108 ms。服务启动加载约 1.5 秒。

### 出处怎么定（同一句可能同时出现在很多首诗里）

一句诗可能同时出现在唐诗、宋人的偈颂、元曲里。**不去删句子**，而是在检索时按可信度打分挑一处：

1. **整句命中优先**（整小句 > 跨小句 > 片段）；
2. **僧人转引垫底**（作者以「释」/「僧」开头）——偈颂里塞满对前人名句的直引，
   不加这条，《达磨大师赞》会凭一个 4 字整句抢走苏轼「大江东去」的出处；
3. **朝代早者优先**——原文早于转引，「落霞与孤鹜齐飞」因此归王勃《滕王阁序》而不是宋人偈颂；
4. **文体**：诗 = 词 > 曲 > 赋 > 文（名句多出自诗词，标注也更自然）。

这一规则确保了名句出处的准确性：例如「落霞与孤鹜齐飞」正确归属为王勃《滕王阁序》（而不是后世禅僧偈颂的转引），「大江东去」正确归属为苏轼《念奴娇》。语料库采用**保留全篇、出处动态打分**机制，避免因全局去重导致诗词上下文残缺。

### 繁简映射与特定单字处理

1. **豁免独立字**：`乾` 与 `徵` 在现代汉语中仍然独立存在（如乾坤、宫商角徵羽），构建语料时不将其简单折叠为「干」或「征」。
2. **口径一致**：语料构建与查询侧使用同一张繁简映射表（`data/t2s.json`），保持两端标准一致。
3. **异文对重查**：支持 `干↔乾`、`唯↔惟`、`着↔著` 等异文对智能重查，既能精准匹配原字，又不会把「干戈」错配到「乾」字格上。

| 古文 10000 篇（古诗文网） | **赋、骈文、散文** | 10,000 篇（赋 309 篇） |

合计 **355,235 篇 → 3,288,184 句 / 1,902 万汉字**。
产物 `data/clauses.txt.gz` 35 MB + `data/poems.json.gz` 4 MB，服务端常驻约 420 MB。

- 诗句与词句同权；散文（`文`）默认也开着，可在建房时关掉（「语料」多选）。
- 古文库里混着诗、赋、散文，按句长自动分类：全五言/七言记为「诗」，标题带「赋」记为「赋」，其余为「文」。
- **多版本共存**：全唐诗底本作「床前看月光／举头望山月」，通行本作「明月光／望明月」，
  两版都在语料里，都能判过。

## 界面

**视觉规范与单机版《飞花斯普拉遁-主持台》同源**，不是另起一套皮肤：设计令牌（`--ink-a` 赤 /
`--ink-b` 青 / `--bg` / `--blank` / `--line` / `--grid` / `--radius` / `--shadow`）、字体栈
（PingFang SC / 微软雅黑）、按钮、卡片、输入框全部照搬；棋盘更是同一套实现 ——
无缝网格（`gap:0` + 逐格边框）、同色相邻格线透明连成墨块、字号 `--cell-fs` 随格宽
（`clamp(9, 格宽×0.54, 36)`）、未涂色格用 `--blank` 底 `--blank-text` 字。

飞花记录、下划线标记（新占墨黑实线 / 抢夺己方笔色 / 己方灰色点状）、结算面板（`winner` +
`winname` + 三栏 `fbox`）、`details` 折叠区，也都是主持台那一套。

只有在线对战才存在的东西才另作设计，且沿用同一套部件：

| 在线版独有 | 复用自 |
|---|---|
| 大厅（建房 / 加入、棋盘与轮数、语料多选） | `.card` + `.formrow` + `.chk` + 主按钮 |
| 3 位数字房号、分享链接 | `.modal` + `.bigcode` + `.copyrow` |
| 每手限时倒计时（默认 120 秒） | 主持台的 `.clock`（运行蓝 / 告急红） |
| 撤销一步 / 提前结算（需对方同意） | 主持台同名功能的协作版：服务端存快照、双方确认 |
| 双方准备后才开局 / 随时暂停 | 协作版新增：`ready` 双方确认；`pause` 冻结倒计时，两边都能恢复 |
| 观众 / 选手随时下场换人 | 协作版新增：`watchers` 观众席，`stand` 下场、`seat` 补位；缺人时自动冻结计时 |
| 未收录句由对方裁决 | 协作版新增：`dispute` 挂起一手、冻结计时，对方判有效 / 重填 |
| 开局设置 + 重抽棋盘 | 主持台顶栏那组字段（尺寸 / 额外字 / 轮数 / 每手秒数 / 文体 + 重抽棋盘）搬进房间，开局前可改 |
| 出手前实时预览 + 命中动画 | 主持台 `preview()` / `colorToken()` / `markChanged()` 整套移植：`pv-new` / `pv-cap` / `pv-hold` 三态 + `flash` 白描边 |
| 裁判 | 协作版新增：选手可把观众标成裁判（可多名、可撤销），掌流程但不给出场 |
| 大厅「当前房间」列表 | 协作版新增：`/api/rooms` 只返回公开信息，可加入的直接给按钮 |
| 导出截图 / 导出 GIF | 主持台 `export` 段整段移植（Canvas 战报 + GIF89a 逐手回放） |
| 判诗回执 | 主持台的 `.msg.ok / .warn / .err` |
| 提交按钮随回合方变色 | 主持台的 `#btnSubmit.team-a / .team-b` |

### 存档与审阅

每局结束（轮数打满 / 棋盘填满 / 提前结算）都会把这一局的配置、双方、比分、每一手和事件流水
**追加**写入 `data/records.jsonl`（超过 8 MB 滚一份 `records.1.jsonl`）；反馈写入 `data/feedback.jsonl`。
用浏览器打开 `/admin?key=<口令>` 就能看，口令在项目根的 `admin.key`（随代码一起发布，本地和线上同一个）。

> 注意：这两个文件活在**服务器运行环境的磁盘**上，发布新版本重建沙箱会一起清空。
> 需要长期留存，先在审阅页点「导出 JSON」。

### 公告栏（改一句话不用重新发布）

大厅顶上有一条公告，正文存在 `data/notice.json`，用 `/admin?key=<口令>` 的「公告」标签改，
**保存即对所有人生效**（前端 30 秒内刷到），不需要重新发布应用。留空保存 = 撤下。

- 读是公开接口（`GET /api/notice`），写要口令。正文 300 字上限，保留换行，只按纯文本渲染。
- 它是运行期状态：**重建沙箱（发布）后会回到「没有公告」**，需要的话发布后重写一条。
- 本地那份 `data/notice.json` 不进版本库，**发布前要删掉**，否则会把一条过时的测试公告带上线。

### 开发者模式（隐形观战 + 大厅可见私密房）

在任意页面地址后面加 `?dev=<口令>`（口令就是 `admin.key`，和审阅页同一个）即可：

- **大厅能看到私密房间**（房号是 5 位字母数字，不带口令根本列不出来）；
- **进任何房间都是「隐形观众」**：不占席位、不进成员列表、不算观众数、不写进出/上下线事件，
  别人看不到你来过；也不会让一个早该散的空房因为你挂着而不散。

口令读出来后立刻从地址栏抹掉、只存 `sessionStorage`，**分享链接永远不会带它**
（`roomLink()` / `selfLink()` 会把当前 query 原样带出去，这条必须守住）。隐形观众没有裁决权和「坐下」按钮 ——
想真的打一局，开一条不带 `dev` 的链接就是普通玩家。

**关闭**：大厅提示条或房间观众条上的「关闭开发者模式」按钮（清掉本地口令并重载一次）。
换个标签页打开普通链接、或清掉该标签页的 `sessionStorage` 也是同样效果。

### 反馈怎么到开发者邮箱

**站点本身不发邮件** —— 收件地址只要出现在任何会被下发的文件里就等于公开了。所以发信这一步在站点外：

```bash
node tools/pull_feedback.js --peek     # 取还没取过的反馈，记下待确认
# 发信成功之后
node tools/pull_feedback.js --commit   # 才记为已读
```

默认 `BASE` 是线上地址、口令读 `admin.key`；本地调试用 `BASE=http://127.0.0.1:8787`。
线上网关要 `sharecode`（不带时所有 `/api` 都 403），脚本默认带仓库里已有的那个值，可用 `SHARECODE=` 覆盖。
输出第一行固定 `NEW_FEEDBACK=<n>`（`0` 没有新的，`-1` 拉取失败），脚本按 `fid` 去重、幂等。
拆成 peek / commit 是为了**发信失败不丢**：先标记再发信，一旦发信失败那几条就永久漏掉了。

`data/feedback.jsonl` 跟着容器一起消失，**发布前必须先取走未读反馈**（见 AGENTS.md 第 8 节）。
细节与硬约束见 AGENTS.md 第 11 节。

**启动记录**（`data/boot.log`，审阅页第三个标签）每次进程启动追加一行，记的是
`prevLines`（启动瞬间这个文件里已经有几条）和 `host`（容器 hostname）：

- `prevLines > 0` → 上一次启动写的内容还在，说明重启后磁盘是延续的；
- `prevLines = 0` → 文件是这一轮新生成的，说明拿到的是干净磁盘。

这个标签只为一件事存在：判断「把对局存盘、重启后读回来」这条保命路线在这个部署环境里成不成立。
**发布前必须删掉本地的 `data/boot.log`**，否则它会被一起打包上线，判据就失真了。

**房间快照**（`data/rooms.snap.json`，审阅页第四个标签）就是那条保命路线本身：进程退出前把在场的
房间完整写一份盘，新进程启动时读回来。三个触发点——状态变化后 1.5 秒内的周期写、收到 `SIGTERM` /
`SIGINT` 时的同步写、未捕获异常时的兜底写。恢复只在「快照不超过 15 分钟」且「`schema` 相同」时进行，
读不到 / 太旧 / 版本不符 / JSON 坏了都只是**一个房间都不恢复**，不会把半套数据塞进内存。
审阅页那一栏直接写「内存里几间 / 快照里几间 / 这一轮接回了几间」。
**发布前也要删掉本地的 `data/rooms.snap.json`**，别让它随包上线。

状态里还带三样跟「人」有关的东西：`members`（赤营 / 青营 / 观众 + `mid` + 在线状态 + 是否是你）、
`youMid`（你自己的稳定标识）、`events`（房间事件流水，最多 400 条）。`mid` 与 token 无关，
对外只暴露 mid，移出成员用它定位；换席位、下场、补位都不变。

**客户端只能发诗句原文**，命中哪些格、涂成什么颜色全由服务端算——前端改不了盘面，
也拿不到语料表（没法离线预演穷举）。

**每条 SSE 连接均按客户端持有的独立 token 生成状态**，确保每个玩家与观众收到的视角和操作权限严格对应其真实席位身份。

## 服务运行与容灾保护

- 这是一个**常驻 Node 进程**（SSE 长连接），不能作为纯静态站点托管。
- 单实例内存约 260 MB；内置了对局连续性保障与断线恢复机制：
  1. **房间快照持久化**（`data/rooms.snap.json`）：房间状态变动或进程收到终止信号时将执行快照落盘；服务重启时自动恢复有效窗口内的房间，对局时钟按真实墙钟平稳转入暂停，避免玩家判负。
  2. **智能断线重连**：网络抖动或短时重启时，客户端平滑浮出重连遮罩并轮询探活，服务恢复后自动刷新盘面收起遮罩。
  3. **掉线宽限与接回**：选手刷新页面或短时掉线时，服务端保留席位 30 秒，超时前同名或同凭据重进均可直接接回原席位。

## 已知限制

- 房间状态活在内存里，靠 `data/rooms.snap.json` 在重启前后接续；**能否真正活下来取决于
  容器重启后磁盘是否延续**（看 `data/boot.log` 的 `prevLines`）。磁盘被换掉时对局仍会丢，
  页面会自己重连，连不上时浮出遮罩，身份存在 sessionStorage，房间不在时会引导回大厅。
- 反向代理需关闭 SSE 缓冲（代码已带 `X-Accel-Buffering: no`）。
- **同朝代用典仍会抢出处**：出处规则只认「僧人 / 朝代 / 文体」，同朝代、同文体的转引分不出来。
  实测「醉翁之意不在酒」落到萧立之《次使长劝农喜晴韵》（宋诗引欧阳修《醉翁亭记》）、
  「人生自古谁无死」落到赵顺孙《病笃吟》（宋诗先于文天祥收录）。判定本身不受影响，
  界面措辞是「见《…》」而不是「出自」，就是为了留这个余地。要彻底解决得维护一张
  高频名句的权威出处表，属另一件事。
- **一次只提交一句**：把多句连写（如「知否知否应是绿肥红瘦」= 4+4+6 三段）会被拒——
  联句拆分只支持两段，且叠句在原诗里本就是重复的两句。
- 每手限时（默认 120 秒）、断线后同一浏览器会话可继续（房间保留 2 小时）；不做观战、不做 AI 对手。
